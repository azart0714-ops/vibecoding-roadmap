1. Гитхаб для хранения версий и кода — только приват репозиторий!

2. Гит для контроля версий и отката на любую из них если ии что-то сломает

3. .env файлы в .gitignore это токены пароли ключи которые должны быть скрыты для других ботов ии ворующих их

4. railway позволяет деплоить сначала на стейджинг сети а не в проде, показывает ошибки, может общаться с основным ии и выяснять проблему, 5$ в месяц, настроить уведомления о лимитах

5. PostgreSQL, Supabase, Neon базы данных, обязательно милилон бекапов, проверять SQL перед выполнением так как ии может «оптимизировать» или почистить базу случайно

6. API Endpoint: API предоставляет два набора конечных точек: один для ресурса «Автор» и один для ресурса «Статья». Доступ к каждому ресурсу можно получить через две разные конечные точки, в зависимости от типа операции, которую клиент хочет выполнить. Например, если клиент заинтересован в просмотре всех авторов в базе данных, он отправит запрос GET в конечную точку /authors. Напротив, конечная точка /authors/:id позволяет клиенту просматривать, обновлять или удалять данные конкретного автора, включая идентификатор автора в качестве параметра запроса.

7. Архитектура проекта: модульная структура по фичам, а не компонентам/сервисам + четкое разделение ответственности, в разных папках разные зоны проекта + Feature-based архитектура

Следи чтобы код не был в одном файле!
