## 🎯 ФУНДАМЕНТАЛЬНЫЕ ПРИНЦИПЫ

### 1. Философия Vibecoding

**Суть**: Vibecoding — это не просто "кодинг с AI", это новая парадигма разработки, где разработчик становится архитектором и дирижером, а AI — исполнителем.

**Ключевые отличия от традиционной разработки**:
- Фокус на архитектуре и планировании, а не на написании кода
- Контроль через документацию и промпты, а не через IDE
- Скорость итераций важнее идеального кода
- Безопасность и откат важнее, чем предотвращение ошибок

### 2. Три точки зрения на проект

Каждый проект должен рассматриваться с трех перспектив:

1. **Бизнес-перспектива**
   - Решает ли проект реальную проблему?
   - Есть ли Product-Market Fit?
   - Какова юнит-экономика?
   - Как быстро можно выйти на рынок?

2. **Пользовательская перспектива**
   - Понятна ли ценность за 5 секунд?
   - Легко ли достичь Aha-moment?
   - Есть ли причины возвращаться (Retention)?
   - Удобен ли интерфейс?

3. **Техническая перспектива**
   - Масштабируема ли архитектура?
   - Безопасны ли данные?
   - Можно ли легко откатить изменения?
   - Поддерживаем ли код?

## 🔐 БЕЗОПАСНОСТЬ И КОНТРОЛЬ

### Критические правила безопасности

1. **GitHub только приватный репозиторий**
   - Публичные репозитории = утечка секретов
   - Боты сканируют GitHub на наличие API ключей
   - Один утекший ключ Anthropic = тысячи долларов убытков

2. **Git для контроля версий**
   - Git — это машина времени
   - Каждый коммит = точка отката
   - Если AI сломал код, просто откатись: `git reset --hard HEAD`

3. **.env файлы ВСЕГДА в .gitignore**
   - Токены, пароли, API ключи НИКОГДА не должны попасть в Git
   - Создавай .env.example с пустыми значениями
   - Проверяй `git status` перед первым push

4. **Railway для staging, не для production сразу**
   - Сначала деплой на staging
   - Тестирование в безопасной среде
   - Только потом production
   - Настрой уведомления о лимитах ($5/месяц)

5. **Базы данных: миллион бэкапов**
   - PostgreSQL, Supabase, Neon — всегда делай бэкапы
   - AI может "оптимизировать" или случайно почистить базу
   - ВСЕГДА проверяй SQL перед выполнением
   - Используй database branching для тестов

6. **Платежи — самая чувствительная часть**
   - Максимальное покрытие тестами
   - Тестирование ТОЛЬКО в sandbox (Stripe test mode)
   - НИКОГДА не делай auto-approve для модуля платежей
   - Перепроверка кода минимум 2 раза
   - Webhook security обязательна

## 🏗 АРХИТЕКТУРА И СТРУКТУРА

### Feature-based архитектура

**Принцип**: Группируй код по фичам, а не по типам файлов

**Плохо** (по типам):
```
/components
/services
/controllers
/views
```

**Хорошо** (по фичам):
```
/features
  /auth
    - components/
    - services/
    - types/
    - tests/
  /payments
  /roadmap
```

**Преимущества**:
- Легко найти весь код фичи
- Легко удалить фичу целиком
- Изоляция изменений
- Понятная структура для AI

### Модульная структура проекта

**Обязательные папки**:
```
project/
├── .claude/              # Память AI
│   ├── SNAPSHOT.md       # Текущее состояние
│   ├── BACKLOG.md        # Задачи
│   └── ARCHITECTURE.md   # Архитектурные решения
├── src/                  # Исходный код
├── skills/               # Навыки и регламенты для AI
├── memory/               # Долговременная память
│   ├── agent_db.json
│   └── long_term_kg.md
├── tests/                # Тесты
├── scripts/              # Утилиты
├── .env                  # Секреты (в .gitignore!)
├── .env.example          # Шаблон переменных
├── .gitignore            # Исключения Git
├── CLAUDE.md             # Контекст для AI
├── handoff.md            # Передача между сессиями
└── README.md             # Документация
```

### API Endpoints структура

**Принцип REST**:
- `/authors` — GET (все авторы), POST (создать)
- `/authors/:id` — GET (один), PUT (обновить), DELETE (удалить)
- `/articles` — аналогично

**Правило**: Один ресурс = два endpoint (коллекция и элемент)

## 💬 ПРОМПТИНГ И РАБОТА С AI

### Мета-промптинг

**Проблема**: Сложно сформулировать детальное ТЗ

**Решение**: Пусть AI сам напишет промпт

**Процесс**:
1. Надиктуй идею голосом (voice-to-text)
2. Отправь AI: "Вот сырая идея. Напиши детальный промпт для себя с ролями, ограничениями и критериями приемки"
3. Проверь и скорректируй промпт
4. Запусти AI с этим промптом

**Преимущества**:
- AI понимает AI-язык лучше
- Экономия времени на формулировках
- Более структурированные ТЗ

### Acceptance Criteria и Definition of Done

**Acceptance Criteria** (Критерии приемки):
```
Когда я нажимаю кнопку X, должно произойти Y
В консоли не должно быть ошибок
Форма должна валидироваться перед отправкой
```

**Definition of Done** (Определение готовности):
- [ ] Код написан и работает
- [ ] Тесты пройдены
- [ ] Нет console.log и отладочного кода
- [ ] SNAPSHOT.md обновлен
- [ ] Коммит сделан с понятным сообщением

### Правило: Каждая задача = новый чат

**Почему**: Контекст переполняется, AI начинает путаться

**Как**:
- Новая фича = новый чат
- Перед стартом: прочитай CLAUDE.md и handoff.md
- После завершения: обнови handoff.md
- Не веди весь проект в одном диалоге

### Multi-Persona Testing

**Метод**: Попроси AI разделиться на 3 персонажа

**Персонажи**:
1. **Core User** — целевой пользователь, лояльный фан
2. **Hater** — скептик, критикует всё
3. **Casual Observer** — случайный прохожий

**Применение**:
```
Разделись на 3 роли: Core User, Skeptic Hater и Casual Observer.
Проведи аудит этой фичи с точки зрения каждой роли.
Выдай структурированный список правок.
```

**Результат**: Множество инсайтов, которые не заметишь сам

## 🔄 УПРАВЛЕНИЕ КОНТЕКСТОМ

### Prompt Caching

**Принцип**: Статические файлы в начале промпта кешируются

**Как использовать**:
1. Помести CLAUDE.md, SNAPSHOT.md, правила в начало
2. Эти файлы закешируются на 5 минут
3. Экономия до 90% стоимости токенов

**Правило**: Если делаешь паузы < 5 минут, кеш не сбрасывается

### Handoff Protocol (Правило 10 шагов)

**Принцип**: Каждые 10 действий AI обновляет handoff.md

**Содержимое handoff.md**:
```markdown
## Что сделано
- Интегрирована БД Neon
- Создана таблица users
- Добавлена авторизация

## Текущие проблемы
- Тест auth.test.js падает из-за несовместимости типов

## Следующие шаги
- Исправить схему типов в auth.types.ts
- Добавить middleware для защиты роутов
```

**Преимущества**:
- Новая сессия начинается с контекста
- Нет потери прогресса
- Легко передать проект другому разработчику

### Стратегии управления контекстом

1. **SELECT** — передавай только нужные файлы
   - Не скармливай весь проект
   - Выбирай только релевантные файлы

2. **COMPRESS** — сжимай историю
   - Попроси AI сделать резюме решений
   - Запиши в документацию
   - Очисти историю чата

3. **WRITE** — выноси во внешние файлы
   - Важная логика → в ARCHITECTURE.md
   - Структуры данных → в types файлы
   - Не зависи от истории чата

## 🎨 ДИЗАЙН И UX

### Design System обязателен

**Проблема**: Повторяешь одну и ту же работу с элементами

**Решение**: Создай Design System в начале проекта

**Что включить**:
- CSS переменные для цветов
- Типографика (размеры шрифтов)
- Spacing (отступы)
- Компоненты (кнопки, карточки, формы)
- Анимации и переходы

**Преимущества**:
- AI использует готовые компоненты
- Консистентный дизайн
- Быстрые изменения (меняешь переменную = меняется везде)

### Правило оптимизации

**Вопрос**: Делаешь что-то много раз?

**Действие**: Спроси AI "Как это оптимизировать и упростить?"

**Примеры**:
- Повторяющиеся тесты → фабрики и фикстуры
- Похожие компоненты → общий базовый компонент
- Дублирование кода → утилиты и хелперы

**Принцип**: Автоматическая блокировка плохого кода

- GitHub Actions
- Линтеры и форматтеры
- Автотесты

**Правило**: Если тесты не прошли, коммит блокируется

### Do Things That Don't Scale (Paul Graham)

**Принцип**: На старте делай всё вручную

**Примеры**:
- Обрабатывай заказы вручную
- Лично общайся с каждым пользователем
- Делай onboarding лично

**Почему**: Проверяешь, нужна ли услуга, до автоматизации

### Retention — главная метрика

**Принцип**: Удержание важнее привлечения

**Как измерять**:
- Когортный анализ
- Day 1, Day 7, Day 30 retention
- Ровная горизонтальная линия = PMF найден

**Фокус**: Сократи путь к Aha-moment

1. Product Hunt

3. Twitter/X

**Правило**: Тестируй каналы последовательно, не все сразу

## ⚠️ ЧАСТЫЕ ОШИБКИ

### 1. Код в одном файле
**Проблема**: AI пишет всё в один огромный файл  
**Решение**: Явно укажи "Следи чтобы код не был в одном файле! Разбей на модули"

### 2. Auto-approve для критичных операций
**Проблема**: AI может удалить данные или сломать платежи  
**Решение**: НИКОГДА не давай auto-approve для БД и платежей

### 3. Отсутствие бэкапов
**Проблема**: AI "оптимизировал" БД, данные потеряны  
**Решение**: Бэкапы перед каждым изменением схемы

### 4. Публичный репозиторий с секретами
**Проблема**: API ключи утекли, счет на $10,000  
**Решение**: Только приватные репозитории + .gitignore

### 5. Весь проект в одном чате
**Проблема**: AI путается, галлюцинирует, забывает правила  
**Решение**: Новая задача = новый чат + handoff.md

### 6. Отсутствие staging
**Проблема**: Баг попал в production, пользователи пострадали  
**Решение**: Всегда тестируй на staging перед production

### 7. Нет code review
**Проблема**: AI добавил уязвимость или плохой код  
**Решение**: Pull Requests + diff-контроль + защита main ветки

### 8. Игнорирование тестов
**Проблема**: Регрессии, баги в production  
**Решение**: E2E тесты для критичных сценариев
