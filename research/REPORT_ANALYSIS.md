### 2. Таксономия шести уровней развития ИИ в разработке

| Уровень | Название | Роль человека | Роль ИИ | Результат |
|---------|----------|---------------|---------|-----------|
| **0** | Традиционная разработка | Полное написание кода | Отсутствует | Ручной синтаксис |
| **1** | Ассистирование (Helper) | Написание с подсказками | Автодополнение, поиск ошибок | Ускорение рутины |
| **2** | Партнерство на основе намерений | Описание целей | Генерация структур и функций | Схемы и логика |
| **3** | Проактивная оптимизация | Надзор за качеством | Рефакторинг, поиск уязвимостей | Чистый код |
| **4** | Автономные агенты | Валидация плана | Самостоятельное редактирование и тесты | Выполненные задачи |
| **5** | Фабрика ПО | Заказчик (Product Owner) | Проектирование, сборка, деплой | Готовое приложение |

**Критический переход**: Уровень 2→3 — ИИ начинает предлагать архитектурные улучшения проактивно

### 3. Методологические циклы и воркфлоу

**Базовый цикл (5 шагов)**:
1. **Describe** (Описание намерения) — формулировка цели на естественном языке
2. **Generate** (Генерация кода) — создание начальной реализации
3. **Run** (Запуск) — выполнение кода
4. **Test** (Тестирование) — проверка результата
5. **Feedback** (Обратная связь) — корректировка

**Профессиональный подход 2026**:
- **MVP/Прототипы**: Чистый вайбкодинг (3-5x ускорение)
- **Промышленный софт**: Агентная инженерия с Plan Mode → Act Mode

### 5. Продвинутые протоколы управления

#### 5.1 .cursorrules / .mdc
Эволюция от простых предпочтений к операционным протоколам:
- Принудительные стандарты кодирования
- Запрет устаревших библиотек
- Обязательная типизация

#### 5.2 Review Gate Protocol
Экспериментальный паттерн:
```python
# final_review_gate.py
# Блокирует терминал до команды TASK_COMPLETE
# Предотвращает "уход" агента в середине процесса
```

#### 5.3 Управление контекстом
**Структура папки .notes**:
- `project_overview.md` — архитектура
- `task_list.md` — приоритеты
- `directory_structure.md` — навигация для агента

**Файл .cursorignore**: Исключение /node_modules, /build для экономии токенов

### 6. Second Brain (Второй мозг) для разработчиков

**Архитектура Карпати**:
```
/raw          → Необработанные материалы (транскрипты, статьи)
/wiki         → Структурированные страницы (создаются агентами)
index.md      → Центральный индекс
agents.md     → Инструкции для агентов (корень проекта)
```

**Процесс**:
1. Добавить материал в /raw
2. Агенты извлекают концепции
3. Создают страницы в /wiki
4. Обновляют index.md

**Consciousness Stream**: Файлы meeting_notes.md или log.md для фиксации решений

### 7. Безопасность и риски

#### 7.1 Статистика
- **45%** сгенерированного кода содержит уязвимости (2026)

#### 7.2 Основные вызовы
1. **Технический долг**: Накопление ошибок без ревью
2. **Гомогенизация софта**: Предпочтение популярных библиотек
3. **Утрата контроля**: Непонимание работы системы

#### 7.3 Минимизация рисков
- Гибридный подход: вайбкодинг + традиционная строгость
- Code review обязателен
- Сканирование уязвимостей перед продакшеном
