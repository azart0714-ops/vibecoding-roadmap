# 🎨 ДИЗАЙН И UI/UX BEST PRACTICES ПОД УПРАВЛЕНИЕМ ИИ (ЭТАП 7)

Этот документ представляет собой всеобъемлющее руководство по созданию премиальных, интерактивных и доступных пользовательских интерфейсов силами ИИ (AI-driven design). Дизайн в эпоху Vibecoding должен быть предсказуемым, декларативным и легким для модификации моделями, обеспечивая при этом максимальный уровень пользовательского опыта (UX).

---

## 📐 1. АРХИТЕКТУРА ДИЗАЙН-СИСТЕМ И COMPONENT-DRIVEN DEVELOPMENT

При верстке силами ИИ использование классического CSS или тяжелых внешних UI-библиотек (MUI, Ant Design) приводит к конфликтам селекторов, перерасходу токенов и сложному Props API. Золотой стандарт Vibecoding — это **Tailwind CSS + Shadcn/ui**.

### 🔹 1.1. Tailwind CSS как Декларативный Стилизатор
ИИ отлично распознает семантику классов Tailwind CSS. Чтобы интерфейс оставался чистым и согласованным:
1.  **Централизованные токены темы**: Все цвета, отступы, скругления и шрифты должны быть жестко зафиксированы в `tailwind.config.js` (или `@theme` в Tailwind v4). ИИ запрещено использовать ad-hoc значения (например, `bg-[#3a2f8b]`), вместо этого модель обязана использовать токены темы (например, `bg-primary-600`).
2.  **Dark Mode из коробки**: Использовать связку `next-themes` и классов Tailwind `dark:`. ИИ должен генерировать семантические пары цветов (например, `bg-white dark:bg-zinc-950` и `text-zinc-900 dark:text-zinc-50`).

### 🔹 1.2. Shadcn/ui — Архитектура "Copy-Paste"
Shadcn/ui не является NPM-зависимостью. Это набор чистых компонентов React на базе Radix UI, код которых копируется напрямую в папку `components/ui`.
*   **DX-эффект для ИИ**: Модели не нужно бороться со сложным Props API закрытой библиотеки. ИИ имеет полный доступ к TSX-коду разметки компонента. Если нужно изменить поведение кнопки или выпадающего списка, ИИ просто переписывает локальный TSX/Tailwind код внутри папки проекта.
*   **Изоляция**: Компоненты UI полностью изолированы, что предотвращает побочные эффекты в других частях системы.

## 🏎️ 2. UX, ВОСПРИНИМАЕМАЯ ПРОИЗВОДИТЕЛЬНОСТЬ (PERCEIVED PERFORMANCE)

Для пользователя важно не реальное время загрузки, а то, как он его воспринимает. ИИ должен автоматически внедрять паттерны ускорения восприятия.

### 🔹 2.1. Skeleton Screens вместо Spinners
Спиннеры загрузки (loading spinners) акцентируют внимание пользователя на ожидании. Скелетоны (Skeleton Screens) создают иллюзию того, что контент уже почти загружен.
*   **Правило для ИИ**: При загрузке блоков данных использовать плейсхолдеры-скелетоны, в точности повторяющие форму будущего контента (размер аватара, количество строк текста, сетку карточек).
*   **Пульсация**: Скелетоны должны иметь мягкую пульсирующую анимацию (`animate-pulse` в Tailwind), чтобы показывать активность процесса.

```tsx
// Пример идеального скелетона для карточки пользователя
export function UserCardSkeleton() {
  return (
    <div className="flex items-center space-x-4 p-4 border border-zinc-200 dark:border-zinc-800 rounded-xl animate-pulse">
      <div className="w-12 h-12 rounded-full bg-zinc-200 dark:bg-zinc-800" />
      <div className="flex-1 space-y-2">
        <div className="h-4 bg-zinc-200 dark:bg-zinc-800 rounded w-1/3" />
        <div className="h-3 bg-zinc-200 dark:bg-zinc-800 rounded w-2/3" />
      </div>
    </div>
  );
}
```

### 🔹 2.2. Optimistic UI Updates (Оптимистичный интерфейс)
Оптимистичный UI мгновенно отображает результат действия (лайк, добавление в корзину, отправка сообщения) локально, не дожидаясь ответа сервера по сети. Если запрос к серверу падает, состояние откатывается назад с выводом уведомления об ошибке.
*   **Реализация**: Использовать хук `useOptimistic` в React 19 / Next.js. ИИ должен быть обучен применять этот паттерн для всех бинарных и быстрых мутаций.

### 🔹 2.3. Исключение "мертвых зон" (Error & Empty States)
*   **Empty States (Пустые состояния)**: Если список пуст, ИИ должен генерировать красивую карточку с иллюстрацией, дружелюбным текстом и явной кнопкой призыва к действию (CTA) (например, "Создать первую задачу").
*   **Error States (Экраны ошибок)**: Любая ошибка должна содержать: понятное описание человеческим языком, технические детали под спойлером (для отладки) и кнопку "Повторить попытку" (Retry) для перезапуска запроса.

## ♿ 3. ДОСТУПНОСТЬ (ACCESSIBILITY / A11Y) И СТАНДАРТЫ WCAG 2.1 AA

ИИ-разработчики часто забывают про доступность, генерируя несемантический HTML (бесконечные кликабельные `<div>`). Роадмап должен жестко требовать соблюдения WCAG 2.1 AA.

### 🔹 3.1. Семантическая верстка и WAI-ARIA
*   Любая кнопка должна быть тегом `<button>`, а не кликабельным `div` с `onClick`. Если кнопка содержит только иконку, обязателен атрибут `aria-label`.
*   Использовать правильные ориентиры: `<header>`, `<main>`, `<nav>`, `<footer>`, `<aside>`.
*   Для динамических элементов (модальные окна, выпадающие списки) использовать библиотеки Radix UI или Headless UI, которые автоматически управляют атрибутами `aria-expanded`, `aria-haspopup`, `aria-controls` и фокусом.

### 🔹 3.2. Навигация с клавиатуры (Keyboard Navigation)
Интерфейс должен быть полностью управляем без мыши:
1.  **Индикатор фокуса (Focus Ring)**: Никогда не отключать outline без замены. Фокус должен быть четко виден (использовать классы `focus-visible:ring-2 focus-visible:ring-primary-500 focus-visible:outline-none`).
2.  **Зацикливание фокуса (Focus Traps)**: В модальных окнах фокус должен быть зациклен внутри окна. При нажатии `Tab` фокус не должен уходить на задний план страницы. При нажатии `Escape` окно должно закрываться.
3.  **Логичный порядок**: Атрибут `tabIndex` должен соответствовать визуальному порядку чтения элементов на странице.

## 🎬 4. ДЕКЛАРАТИВНЫЕ МИКРО-АНИМАЦИИ (FRAMER MOTION) И ИНСТРУМЕНТЫ ГЕНЕРАЦИИ UI

Анимации оживляют интерфейс, повышая вовлеченность. Однако императивные анимации через манипулирование CSS-классами сложны для генерации ИИ. Решение — **Framer Motion**.

### 🔹 4.1. Декларативная анимация с Framer Motion
Framer Motion позволяет ИИ описывать анимацию в виде простых JavaScript-объектов прямо в пропсах компонента:
*   ИИ должен использовать пропсы `initial`, `animate`, `exit` и `transition`.
*   При анимации списков (добавление/удаление элементов) использовать компонент `<AnimatePresence>` для плавного исчезновения удаляемых элементов из DOM.

```tsx
import { motion, AnimatePresence } from 'framer-motion';

// Идеальный паттерн для плавного выпадающего списка
export function AnimatedDropdown({ isOpen, children }: { isOpen: boolean; children: React.ReactNode }) {
  return (
    <AnimatePresence>
      {isOpen && (
        <motion.div
          initial={{ opacity: 0, y: -10, scale: 0.95 }}
          animate={{ opacity: 1, y: 0, scale: 1 }}
          exit={{ opacity: 0, y: -10, scale: 0.95 }}
          transition={{ duration: 0.15, ease: 'easeOut' }}
          className="absolute right-0 mt-2 w-56 rounded-xl bg-white dark:bg-zinc-950 p-2 shadow-lg border border-zinc-200 dark:border-zinc-800"
        >
          {children}
        </motion.div>
      )}
    </AnimatePresence>
  );
}
```

### 🔹 4.2. Промптинг для v0.dev и интеграция в проект
v0.dev от Vercel — мощнейший генератор интерфейсов. Правила интеграции UI из v0:
1.  **Модульный перенос**: Запретить ИИ копировать всю сгенерированную страницу в один файл. Компоненты должны нарезаться на атомарные блоки (карточки, кнопки, хедер) и складываться в соответствующие папки.
2.  **Удаление дубликатов**: При импорте кода из v0 ИИ должен заменить встроенные SVG-иконки на импорт стандартных иконок из библиотеки `lucide-react`.
