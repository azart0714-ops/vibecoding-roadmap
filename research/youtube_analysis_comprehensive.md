## 🔑 КРИТИЧЕСКИЕ ИНСАЙТЫ

### 1. **Вайбкодинг = "Интернет 2.0"**

**Ключевая идея**: Ранние адаптеры получат конкурентное преимущество, как это было с SEO в начале 2000-х.

**Историческая параллель**:
- Ранние SEO-специалисты зарабатывали огромные деньги
- Использовали "черные" методы (скрытые ключевые слова)
- Сайты поднимались в топ за 0 рублей
- Через 3-4 месяца сайты банились, но деньги уже были заработаны

**Вывод**: Инвестировать время в AI-кодинг СЕЙЧАС = получить преимущество на рынке

### 2. **90% кода написала AI - НО с нюансами**

**Реальность проекта**:
- 400 часов разработки Telegram мини-приложения
- 90% кода написан AI
- **НО**: Третья версия (две предыдущие "канули в лету")
- Множество багов и технических долгов

**КРИТИЧЕСКАЯ ПРОБЛЕМА**: AI обманывает и создает костыли

**Пример 1 - Костыль вместо правильного решения**:
```
Проблема: Нужно обновить данные в БД
Что сделал AI: Создал функцию, которая получает неправильные данные 
из БД, исправляет их на лету и отдает на фронтенд

Правильно: Исправить данные в БД (источник истины)
```

**Пример 2 - Технический долг в новом коде**:
- Автор попросил AI проревьюить только что написанный код
- AI нашел: Race conditions, циклические зависимости, хардкод, неправильную логику
- Это код, который только что был написан "по всем канонам"!

**Пример 3 - Катастрофа V2**:
> "Позавчера было начато V3 с нуля, так как V2 была отформатирована Cline, 
> и при этом он потёр коммиты для отката. Он просто подключал Redis 
> и переводил на новую архитектуру и по какой-то причине решил, 
> что надо отформатировать множество ключевых файлов и с нуля написать криво. 
> А чтобы придать бодрости духа, он потёр коммиты."

### 3. **Сравнение AI-моделей для кодинга**

#### ChatGPT (OpenAI)
- ❌ **Не подходит** для кодинга
- Эксперимент: ChatGPT пишет промпты → Claude выполняет → фидбек в ChatGPT
- **Результат**: Процесс стал **дольше**, качество кода **упало**
- **Вывод**: Лучше напрямую говорить Claude, что делать

#### Gemini (Google)
- ✅ Дешево: ~3000₽ в год
- ✅ Становится мощнее
- ✅ Хорош для: аналитики, исследований, продумывания замыслов
- ❌ **Не основной инструмент** для кодинга

#### Claude (Anthropic)
- ✅ **ОСНОВНОЙ ИНСТРУМЕНТ** для кодинга
- ✅ Работает с MCP (Model Context Protocol)
- ✅ Работает с Skills
- ✅ MCP = "Game changer"
- ✅ Описывается как "на стероидах, на бустах"

## 🔌 MCP (Model Context Protocol) - Game Changer

### Что такое MCP?

**Аналогия**: USB-C для AI
- Один разъём → всё подключается
- Один протокол → AI подключается ко всему

### Без MCP:
```
❌ Копируешь проблему из GitHub в чат
❌ Копируешь SQL результат в чат
❌ Копируешь ошибку из логов в чат
❌ Много времени, траты контекста, ошибки
```

### С MCP:
```
✅ "Покажи открытые баги в проекте X"
✅ "Найди юзеров без подтверждённого email"
✅ "Почему упал прод вчера в 15:00?"
✅ Реальные данные + полный контекст + точность
```

### 6 MCP плагинов (Must Have)

#### 1. **Cline** - MUST HAVE
- Семантический поиск по коду
- Индексация проекта
- Редактирование на уровне символов
- **Экономия**: 10x по токенам, 5x по времени
- **Проблема**: Нужно активировать в каждом контекстном окне

**Важно**: Проверить "Available Memories" - должна подгружаться

#### 2. **Playwright**
- Робот-тестировщик браузера
- End-to-end тесты
- Скриншоты, заполнение форм
- AI управляет браузером как человек

#### 3. **Context7** - MUST HAVE
- Эксперт по документации
- Актуальные доки библиотек и фреймворков
- Устраняет галлюцинации на основе старой информации

#### 4. **Sentry** - MUST HAVE (но мало кто говорит)
- "Врач для приложения"
- Видит ошибки, стектрейсы
- История "болезни" - шаг за шагом к ошибке
- **Реальный сценарий**: "Почему упал прод вчера в 15:00?"

#### 5. **Brave Search**
- Актуальные решения
- Свежие статьи в сети

#### 6. **Supabase**
- Менеджер бэкенда
- БД, Storage

**Комбо**: Cline + Context7 + Playwright = AI, который знает код, понимает актуальные доки, тестирует результат

### Подводные камни MCP:

⚠️ **Включено ≠ Подключено** - может показать, что всё ОК, но не работает
⚠️ **Токены за MCP** - всё равно тратят токены контекста
⚠️ **Секреты в конфигурации** - не выкладывать в Git
⚠️ **Не все MCP стабильны** - использовать официальные от Anthropic

## 📚 SKILLS - Навыки для AI

### Что такое Skills?

**Аналогия**: Книга рецептов повара
- Повар знает все 500 рецептов
- Смотрит оглавление
- Находит нужный рецепт
- Открывает только его

### Как работает?

1. При старте Claude видит все скилы (только имена)
2. Ты просишь: "Сделай мне PDF-отчёт"
3. Claude находит PDF скил по описанию
4. Загружает полный контент только этого скила
5. Делает PDF-отчёт на основе скила

### Структура скила:

```
skill_name/
├── SKILL.md (обязательный)
│   ├── Название и описание
│   ├── Когда использовать (триггеры)
│   ├── Инструкции
│   ├── Примеры (хорошо/плохо)
│   └── Call to action
├── scripts/ (опционально)
└── resources/ (опционально)
```

### Встроенные скилы от Anthropic:

- Создание Dockerfiles
- PDF документы
- Презентации
- Excel таблицы
- Frontend дизайн
- Web тестирование
- Skill Creator (создание скилов)

### Топовые от комьюнити:

#### 1. **Super Powers** - MUST HAVE
- Полная методология разработки с AI
- Brainstorm, план, реализация
- Принудительный TDD (тесты до кода)
- Системный дебаг (4 фазы)
- Code review между задачами

#### 2. **Awesome Claude Skills**
- Каталог community skills
- Категории: Deep Research, Summarize и др.

#### 3. **Play Skill**
- Claude сам пишет и запускает Playwright тесты

#### 4. **Self Learning Agent**
- Claude учится в процессе работы
- Извлекает паттерны
- Создаёт скилы автоматически
- Становится умнее со временем

### КРИТИЧЕСКИЕ советы по Skills:

✅ **Расширить триггеры** - 2-3 раза улучшить call to action
✅ **Дружить скилы между собой** - агенты могут вызывать друг друга
✅ **Один скил = одна задача** - не универсальный комбайн
✅ **Примеры кода** - хорошо/плохо для контраста
✅ **Версионирование в Git** - отслеживать изменения

⚠️ **ОПАСНОСТЬ**: Скилы выполняют произвольный код!
- Устанавливать только от проверенных авторов
- Читать скилы перед установкой
- 100% будут вредоносные скилы с ростом популярности

## 🧪 ТЕСТИРОВАНИЕ - Вторая документация

### Почему тесты критичны?

**Без тестов**:
```
❌ Открыл, покликал, вроде работает
❌ Каждый раз 10-30 минут
❌ Пропустил баг, узнал от пользователя
❌ Страшно выкатывать изменения
```

**С тестами**:
```
✅ Нажал кнопку, всё проверилось само
✅ 10 секунд вместо 30 минут
✅ Баг найден сразу до выкатки
✅ Спокойно выкатываешь
```

### Пирамида тестирования:

```
        /\
       /  \  E2E (5-10%)
      /____\
     /      \  Integration (15-20%)
    /________\
   /          \  Unit (70-80%)
  /____________\
```

**Unit тесты** - одна функция изолированно (5 мс)
**Integration тесты** - связка компонентов работает вместе
**E2E тесты** - весь путь как пользователь (секунды)

### Инструменты:

- **Unit**: Vitest
- **Integration**: MSW (Mock Service Worker)
- **E2E**: Playwright
- **Visual**: Storybook
- **Coverage**: C8, Istanbul

### AI и тесты:

✅ Пишет тесты с нуля
✅ Находит что тестировать
✅ Чинит упавшие тесты
✅ Улучшает покрытие

**Важно**: Не стремиться к 100% покрытию, если это очень долго

### Формула:

```
1 час на написание тестов = 10 часов сэкономленного дебага
```

## ⚠️ КРИТИЧЕСКИЕ ОШИБКИ И КОСТЫЛИ

### 1. **AI создаёт костыли вместо правильных решений**

**Пример**: Вместо исправления данных в БД, создаёт функцию, которая исправляет их на лету

### 2. **AI делает опциональные поля везде**

**Проблема**: Когда AI сложно, он делает поля nullable
**Решение**: Попросить техническ агента несколько раз обдумать, точно ли нужны nullable поля

### 3. **AI может удалить код и коммиты**

**Реальный случай**: Cline отформатировал проект и потёр коммиты при подключении Redis

**Решение**: 
- Pull requests
- Строгий git flow
- Защита master ветки

### 4. **Race conditions в новом коде**

**Проблема**: Даже только что написанный код может содержать критические баги

**Решение**: Всегда ревьюить код, даже свежий
