### 5. **Цикл Улучшения Промптов**

**Итеративный процесс**:
1. Начать разработку с исходным промптом
2. Столкнуться с ошибками в реализации
3. Добиться исправления
4. Попросить ИИ проанализировать проблемы и улучшить промпт
5. Обновить промпт и продолжить разработку

**Результат**: Промпт эволюционирует от технических инструкций к фокусу на корректном донесении идей.

**Пример эволюции** (автор обещал выложить финальные промпты в Telegram):
- Промпт для Swift разработки прошел "множество циклов качественных доработок"
- Задача решается за **2-4 итерации** (в лучшем случае)
- Оптимизация кода сокращает базу на **30-50%**

### 6. **Критическая Роль Логов**

**Цитата**:
> "На одних хороших промптах далеко не уедешь. Вам необходимо получать обратную связь от того, что сделала нейронка. Делается это через логи и является краеугольным камнем в процессе разработки."

**Алгоритм работы с логами**:
1. Тестировать функцию → копировать логи в чат
2. Объяснить проблему → попросить анализ **без написания кода**
3. Если анализ устраивает → попросить исправления
4. Повторять цикл до правильного результата
5. Если итераций слишком много → доработать промпт

**Дополнительно**: Вести файл логов разработки с удачными/неудачными решениями для будущих чатов.

### 7. **Техника "Пишу из Будущего"**

**Инновационный подход**:
- ИИ предлагает решение
- Вы тестируете → не работает
- Возвращаетесь к **предыдущему сообщению** и редактируете его
- Пишете: "Пишу из будущего, твое решение не заработало, вот логи, скорректируй подход"
- При отправке код откатывается, но логи остаются

**Преимущество**: Получаете сухой остаток от проверенной гипотезы без захламления чата.

### 8. **Git Workflow для Вайбкодинга**

**Базовые принципы**:
- Git = "сохранение в игре"
- Коммиты делать поэтапно, не все файлы сразу
- Использовать `.gitignore` для исключения сервисных файлов
- Ветки для изоляции фич (опционально для соло-разработки)
- Conventional Commits для описаний

**Автоматизация**:
- Git Hooks для запуска тестов при коммите
- GitHub Actions для CI/CD
- Автоматическая сборка и деплой приложения

### 9. **Стратегия Разработки: От Неопределенности к Определенности**

**Динамика контекста**:
```
Высокая неопределенность → Низкая неопределенность
(Малые итерации)         → (Крупные блоки)
```

**На старте**:
- Описать основную идею (общий контекст)
- Определить **одну ключевую функцию**
- Выбрать язык/платформу
- Разрабатывать малыми функциональными блоками

**По мере роста кодовой базы**:
- База становится ограничивающими рамками для ИИ
- Можно вести разработку более крупными блоками
- Большие планы полезны для аудита/рефакторинга/портирования

### 12. **Монетизация и Лицензирование**

**Стек**: PHP + MySQL + YooKassa

**Стратегия разработки**:
1. Сначала разработать все типы лицензионных ключей **без оплаты**
2. Протестировать ограничения функциональности для каждого тарифа
3. Только потом интегрировать платежный шлюз

**Преимущество**: ИИ имеет полный контекст всех точек интеграции, тестирование происходит сразу.

### 13. **Webflow + Внешние Скрипты**

**Подход к веб-части**:
- Дизайн в Figma за пару вечеров
- Верстка в Webflow за пару вечеров
- Интеграция с backend через внешние скрипты

**Техника интеграции**:
1. Купить простой хостинг + домен
2. Подключить Cursor к хостингу по FTP
3. Встроить ссылку на скрипт в Webflow
4. Использовать кастомные атрибуты как идентификаторы
5. ИИ пишет скрипт, который автоматически загружается на хостинг

**Пример**:
```html
<div order-info="period"><!-- ИИ передает период подписки --></div>
```

### 14. **Автоматическое Тестирование**

**Типы тестов**:
- **Unit** — тестирование функций "в вакууме"
- **Integration** — тестирование связки функций, имитация пользовательского взаимодействия

**Стратегия**:
- Создать отдельный файл инструкций для тестирования
- Покрывать тестами после ручного тестирования функции
- Тесты фиксируют работоспособность текущей версии
- Git Hooks запускают только тесты измененных файлов
- GitHub Actions прогоняют все тесты перед релизом

**Альтернативный подход**: TDD (Test-Driven Development) — сначала тесты, потом код. ИИ хорош в предусмотрении пограничных случаев.

### 17. **Cursor vs Replit**

**Cursor**:
- ✅ Глубокая интеграция на уровне IDE
- ✅ Полный контроль над инфраструктурой
- ✅ Собственная кодовая база
- ✅ Возможность командной разработки после MVP

**Replit**:
- ❌ Ничего не запускалось (на момент тестирования)
- ❌ Блокирует на своей экосистеме
- ❌ Полный цикл без контроля
- ❌ Сомнительная ценность

### 18. **Принцип Единой Ответственности**

**Структура файлов**:
- Один файл = одна ответственность
- Средний размер оптимизированного файла: **~300 строк кода**
- README.md как "оглавление книги" для нейросети
- ИИ адресно редактирует только нужные файлы

**Преимущество**: Не перегружается контекстное окно.

### 19. **MCP Sequential Thinking**

**Рекомендация**: Использовать `mcp sequential-thinking` для разбивки запроса на последовательность действий.

**Эффект**: Задачи решаются лучше, а порой вообще не решаются без MCP.

### 20. **Формулирование Запросов**

**Структура запроса**:
```
{{ТЕЛО_ЗАПРОСА}}

Предоставь анализ в соответствии с инструкциями /dev-swift. 
Код пока не пиши.
```

**Рекомендуемый подход**:
1. Прикрепить корневой `README.md` в начале чата
2. Правило "Одна фича – один чат"
3. Первый этап — аналитика на основе инструкций
4. Второй этап — "Реализуй" (ИИ имеет полный контекст)

**Преимущество**: Исключается принятие решений "на лету".

### 21. **Алгоритмы в Промптах**

**Цитата**:
> "Нейросети очень хорошо воспринимают алгоритмы действий в промптах."

**Пример алгоритма автоподмены**:
```
1. Пользователь начинает печатать слово в неправильной раскладке
2. Система анализирует каждый символ как префикс на основе словарей
3. Как только префикс становится однозначно определяемым, 
   система производит замену
4. После замены происходит переключение системной раскладки
```

### 22. **Борьба с Fallback'ами и Таймингами**

**Проблемы ИИ**:
- ❌ Любит создавать fallback'ы (запасные функции)
- ❌ Любит добавлять таймеры и delay'и

**Решение**:
- Определить единый метод, который работает везде
- Выстраивать работу вокруг него
- Ограничивать ИИ через промпт
- Отдавать приоритет событийной логике над временной

**Цитата**:
> "Все должно работать с первого раза."

### 23. **Роль Детектива**

**Важный навык**:
> "Важно обращать внимание, какую мысль выстраивает ИИ и какой логике следует. Придется читать каждый анализ, чтобы понимать намерение. Вы становитесь детективом, для которого важна каждая деталь."

**Пример**: Пара фраз из чата может дать зацепку для уточняющих вопросов и устранения ошибки.

### 24. **Cursor Commands (/commands)**

**Эволюция**:
- Раньше: Cursor Rules (общие правила)
- Сейчас: `/commands` (удобный вызов из поля ввода)

**Преимущество**: Явный вызов инструкций, ИИ не ленится и не игнорирует правила.

### 25. **Выход из Зависшей Консоли**

**Проблема**: Cursor может самостоятельно выполнять команды, которые приводят к зависанию.

**Решение**:
1. Перейти в консоль Cursor
2. Находясь на последней строке нажать `Ctrl+C`
